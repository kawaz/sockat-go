# DR-0009: 経路は公開せず、試験はパッケージ内から環境を差し替えた world で経路を強制する

- Status: Accepted
- Date: 2026-11-18

## Decision

- 経路は内部の値 (`route`) で、公開 API には診断の名前 (`Route`・`Skipped`) として出るだけ。経路を選ぶ・組み合わせる口は作らない
- 試験はパッケージ内 (`package sockat`) に置き、各経路の関数を直接呼んで強制する
- 環境を読む部分は `config` にして試験から差し替える: B の置き場 (`/tmp` の代わりの場所、`$XDG_RUNTIME_DIR` と `$TMPDIR` の読み方)、`/proc` の場所、`PrivateTmp` で隔離される場所、bind が symlink を辿るか、スレッドの cwd を試すか、乱数の名前の作り方。試験は `config` を差し替えた `world` を自分で作る ([DR-0019](DR-0019-places-held-by-world.md))
- 試験バイナリの `TestMain` は、公開 API の `defaultWorld` を試験専用の置き場 (`/tmp` の下に作る mode 1777 のディレクトリ。`$XDG_RUNTIME_DIR` と `$TMPDIR` は使わない) に向け、終わりにその置き場を丸ごと消す。子プロセスは親の置き場を環境変数で受け取って使い、消さない
- cwd やシグナルのようにプロセス全体に効く設定を変える試験と、生きているプロセスの D が要る試験 (`Sweep`) は、試験バイナリを子プロセスで起こして中で行う

## 理由

- 利用者は経路を知る必要が無い (SPEC)。環境を差し替えられれば、`/proc` の無い Linux、seccomp で `unshare` が断られる環境、置き場が使えない環境、bind が symlink を辿らない OS を、手元と CI で再現できる
- 試験が本物の `/tmp/sockat-<uid>` を使うと、同じ利用者の他のプロセス (並行して走る他の言語の試験を含む) が共有する B を使い、消しうる。試験専用の置き場なら、試験の後に残骸も残らない。1777 にするのは、別の uid に落とした子プロセスもそこに B を作れるように (`/tmp` と同じ)

## 判断の出所

- SPEC の「各実装に求めること」に従う 2026-11-18
- 試験の置き場を分けること: 実装側の判断 2026-11-21
