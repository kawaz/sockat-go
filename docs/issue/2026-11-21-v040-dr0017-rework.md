# v0.4.0 — ハブの DR-0017 (resolve と使い回す置き場) で作り直す

ハブの統括 (session 25352bb6) の依頼 (2026-11-21、ハブ main a91cf52b)。ハブの [DR-0017](https://github.com/kawaz/sockat/blob/main/docs/decisions/DR-0017-resolve-through-persistent-base.md) を、[SPEC](https://github.com/kawaz/sockat/blob/main/docs/SPEC-ja.md) (約束) と [SPEC-routes](https://github.com/kawaz/sockat/blob/main/docs/SPEC-routes-ja.md) (経路の作り方) どおりに実装する。適合試験の CLI はハブの docs/design/conformance.md の新しい入出力に合わせる。

## 依頼の要点

- resolve で、元のパスと同じ所を指し続ける短い綴りを作る (利用者ごとの B → プロセスごとの D (flock) → E の symlink。置き場は /tmp → $XDG_RUNTIME_DIR → $TMPDIR → ソケットのディレクトリ。綴りは procB → B の実パス)
- 既定の bind も綴りを残す。既定の connect は状態を残さない
- fork はしない (UseLastResort 等を消す)
- losses を綴りの性質 (Spelling) に、discard を remove にする
- 関数は SPEC の「関数」に合わせ、形は Go の慣習で決める (datagram の Listen / Dial 系、resolve の 2 つ、Sweep、Options の UsableCrossUID と Base)
- SEQPACKET と datagram の send_to は未決なので作らない
- widened を作れない扱いは今のまま (外すかは Go 側で判断してハブに知らせる)
- 互換は気にしない (利用者は kawaz のプロダクトだけ)。古い API・経路・文書は残さず消す

## 決まり

- SPEC と食い違う所・SPEC で決まらない所は、直し方を決める前にハブの統括に知らせる (推測で埋めない)
- 版は v0.4.0 の見込み。publish は全言語が揃ってハブの適合試験が通り、kawaz の OK が出てから。それまで push も bump もしない (手元の commit で進める)
- ハブの `just conformance` (手元と `--on linux`) で 3 言語の差を見る
- 進み具合と詰まった所を節目でハブの統括に send する

## ハブで追加中の細部 (決まり次第知らせが来る)

- 診断の base に Options.base の時の値 (given の予定)
- link-dir / link-file で bind して失敗した時は E を消してからエラー

1. 設計の読み込みと実装計画、SPEC で決まらない所の洗い出し (ハブへ問う)

### 公開 API

package は `sockat` 1 つ (子 package を作らない)。

```go
// stream
func Listen(path string) (*net.UnixListener, error)
func Dial(path string) (*net.UnixConn, error)
func ListenEx(path string, o Options) (*net.UnixListener, *Bound, error)
func DialEx(path string, o Options) (*net.UnixConn, Report, error)

// DGRAM
func ListenUnixgram(path string) (*net.UnixConn, error)
func DialUnixgram(path string) (*net.UnixConn, error)
func ListenUnixgramEx(path string, o Options) (*net.UnixConn, *Bound, error)
func DialUnixgramEx(path string, o Options) (*net.UnixConn, Report, error)

// resolve
func ResolveForBind(path string, o Options) (*ForBind, error)
func ResolveForConnect(path string, o Options) (*ForConnect, error)

// 置き場
func Sweep() error
func SweepBase(base string) error

type Options struct {
	UsableCrossUID bool   // bind 系だけが見る
	Base           string // B そのもののパス。"" は指定しない
}

type Bound struct {
	File     *SocketFile
	Spelling Spelling
	Route    string // 診断用
	Base     string // 診断用。綴りが B を通らない時は ""
	Skipped  []Skip // 診断用。nil にしない
}

type Report struct {
	Route   string
	Skipped []Skip
}

type Skip struct{ Name, Reason string }

type SocketFile struct{ /* 非公開 */ }
func (f *SocketFile) Remove() error  // ソケットのファイルを 1 回だけ消し、Cleanup もする
func (f *SocketFile) Cleanup() error // E を 1 回だけ片付ける

type ForBind struct {
	Path     string // std に渡す綴り
	Spelling Spelling
	Route    string
	Base     string
	Skipped  []Skip
	// 非公開の項目 (元のパス、E、resolve の時の cwd)
}
func (f *ForBind) Cleanup() error
func (f *ForBind) SocketFile() (*SocketFile, error) // bind した後に呼ぶ

type ForConnect struct {
	Path    string
	Route   string
	Skipped []Skip
}
func (f *ForConnect) Cleanup() error

type SpellingKind int
const (
	Original SpellingKind = iota + 1
	CwdRelative
	Linked
	Dangling
)
func (k SpellingKind) String() string // "Original" 等 (SPEC の名前)

type Until int
const (
	UntilProcess Until = iota + 1
	UntilCleanup
)
func (u Until) String() string // "Process" / "Cleanup"

type Spelling struct {
	Kind SpellingKind
	// 以下は Kind == Linked の時だけ意味を持つ
	Removable            bool
	Until                Until
	UsableCrossUID       bool
	UsableWithPrivateTmp bool
}

type RouteError struct {
	Route   string // 実際に bind / connect して失敗した経路。無ければ ""
	Skipped []Skip
	Err     error
}
func (e *RouteError) Error() string
func (e *RouteError) Unwrap() error
```

形の選び方 (案が複数ある所):

| 所 | 推し | 理由 | 採らない案 |
|---|---|---|---|
| `_ex` の戻り値 | 標準の型・情報の struct・error の 3 値 | 第 1 戻り値が標準の型のままで `Listen` から置き換えやすい。stream と DGRAM で同じ `*Bound` を使え、generics が要らない | `Bound[S]` (generic の struct に socket を入れる): 2 種類のためだけに型引数が要る<br>4 値以上を並べる: `remove`・`cleanup`・`Spelling`・診断で数が増えすぎる |
| 消す口 | `*SocketFile` の method 2 つ | `Remove` と `Cleanup` の 2 口があり、`ListenEx` と `ForBind.SocketFile()` が同じ物を返すので型にする | `func() error` を 2 つ返す: 2 つの関数が同じ E を片付けることが型に出ない |
| `Spelling` | `Kind` と属性を持つ struct | `==` で比べられ、`switch s.Kind` で分岐できる。属性は `Linked` だけが使う | sealed interface と型 switch: 値の比較ができず、Go の標準に例が少ない |
| `Kind` のゼロ値 | 使わない (`Original` は 1) | 失敗時のゼロ値の `Spelling` を `Original` と読ませない | |
| `Options.Base` | `string`、`""` は指定しない | Go の標準の Config 系と同じ (ゼロ値が既定) | `*string`: 呼び出しが書きにくい |
| `DialEx` の診断 | `Report` (値) | 項目が 2 つで、失敗時はゼロ値 | |

エラー:

| 関数 | エラーの型 |
|---|---|
| `Listen`・`Dial`・`ListenUnixgram`・`DialUnixgram` | 標準と同じ `*net.OpError` (`Op` は `listen` / `dial`、`Net` は `unix` / `unixgram`、`Addr` は呼び出し元のパス、`Err` は `*os.SyscallError`)。経路の綴りはエラーに出さない |
| 各 `Ex` | `*RouteError`。`Unwrap` で上の `*net.OpError` に届く |
| `ResolveForBind`・`ResolveForConnect` | `*RouteError`。`Err` は `*os.PathError` (`Op` は `resolve`、`Path` は呼び出し元のパス) |
| `(*ForBind).SocketFile`・`Remove`・`Cleanup`・`Sweep`・`SweepBase` | `*os.PathError` (複数あれば `errors.Join`) |
| 引数の誤り (SPEC「エラー」) | `syscall.EINVAL` を包んだ上の型 |
| 一般のエラー (relative の途中で cwd が変わった) | errno を持たないエラーを包んだ上の型 |
| `Options.Base` のエラー | `ENOENT` / `ENOTDIR` / `EPERM` を包んだ上の型。`Ex` では `RouteError.Route` は `""` |

`Remove` の約束 (覚える時、相対パスの cwd の確かめ、消さない時も nil、listener を閉じない) は SPEC「`remove`」のまま。`ListenEx`・`ListenUnixgramEx` の listener は `SetUnlinkOnClose(false)` (DGRAM の `*net.UnixConn` は元から Close で消さない)。

既定の `Listen` の listener の Close (ハブの答え待ち、下の一覧の 3):

| 通った経路 | `SetUnlinkOnClose` | Close で起きること |
|---|---|---|
| standard | 触らない | 標準のまま (元のパスのファイルが消える) |
| link-dir | 触らない | 綴りの途中の E を辿って、元のパスのファイルが消える |
| link-file | 触らない | E が消え、ファイルは残る |
| thread-cwd・at (`Dangling`) | `false` | 何も消さない (どこにも届かない綴りを cwd からの相対で unlink しに行かせない) |

`world` (環境と、プロセスで覚える物):

```go
type world struct {
	cfg       config
	mu        sync.Mutex
	auto      *base            // 置き場 1〜3 の B
	autoCross *base            // usable_cross_uid の B (auto と同じ所なら同じ *base)
	sockdir   map[fileID]*base // 置き場 4 の B。鍵はソケットのディレクトリ
	given     map[fileID]*base // Options.Base の B。鍵は B の (st_dev, st_ino)
	checked   map[string]bool  // 途中の確かめが済んだ親の実パス
}

type base struct {
	fd       int    // B (閉じない)
	real     string // B の実パス
	kind     string // "tmp" / "runtime" / "tmpdir" / "sockdir" / "given"
	crossUID bool   // B までの途中と B 自身が全部 other に x を持つ
	tmpPath  bool   // 置き場の realpath する前のパスか実パスが /tmp・/var/tmp を通る
	mu       sync.Mutex
	d        *dir   // (プロセス, B) の D。要る時に 1 度だけ作る
	nextE    uint64 // resolve の E のカウンタ
}

type dir struct {
	fd   int    // D。flock (共有ロック) を掛けたまま持つ (閉じない)
	name string
}
```

- 公開 API は package の変数 `defaultWorld` を使う。試験は `config` を差し替えた `world` を自分で作る
- B と D の fd は `int` で持つ (`*os.File` にすると finalizer が閉じる)。全部 close-on-exec
- `config` が持つ物: `/tmp` の場所、`$XDG_RUNTIME_DIR` と `$TMPDIR` の読み方 (既定は呼び出しのたびに環境変数を読む。空と相対パスは使わない)、`/proc` の場所、スレッドの cwd を試すか、bind が symlink を辿るかの表の上書き、乱数の名前の作り方
- 短いパスでは `world` に触らない (環境変数も読まない)

B (SPEC-routes「B の作り方」「実体の置き場」「別の uid と PrivateTmp」のとおり):

| 項目 | 作り方 |
|---|---|
| 置き場の順 | `/tmp` → `$XDG_RUNTIME_DIR` → `$TMPDIR` → ソケットのディレクトリ。`UsableCrossUID` の時は、途中と B 自身が全部 other に x を持つ所だけ |
| 名前 | `sockat-<実効 uid>`、`$XDG_RUNTIME_DIR` の下は `sockat`、ソケットのディレクトリの下は `.sockat.<乱数 10>`。確かめに外れたら同じ置き場の `sockat-<uid>.<乱数 10>` |
| 手順 | 置き場を realpath → 途中を全部確かめる (`world.checked` に覚える) → 親を `O_RDONLY \| O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC` で開く → `mkdirat(0700)` → 作った物を同じフラグで開く → `fstat` (実ディレクトリ・持ち主が実効 uid) → `fchmod(0711)`。`EEXIST` は開いて確かめ (実ディレクトリ・持ち主が実効 uid・`mode & 022 == 0`)、mode は変えない |
| 覚える | 作れた B を `world` に覚え、以後の呼び出しで使う (既定の connect が作った B も)。作れなかったことは覚えず、次の呼び出しでまた順に試す |
| 先に見積もる | 置き場の実パスの長さから綴りが収まらないと分かる時は作らない (`link.go`) |
| `Options.Base` の確かめ | 長いパスで、ソケットのディレクトリを引いた後・経路を試す前に、bind でも connect でも行う (短いパスでは見ない)。親を realpath し、途中と、既にあれば B 自身を確かめる。何も作らない。外れたら `ENOENT` / `ENOTDIR` / `EPERM` で、`Route` は `""`、`Skipped` は空 (`standard` も入れない)、他の置き場を試さない。`UsableCrossUID` と一緒の bind 系は途中と B 自身の other の x も確かめる |
| `Options.Base` の B を作る | B を使う経路 (link-dir・link-file・thread-cwd・at、connect の link-file) に来た時だけ、上と同じ手順で作る |

D と E (SPEC-routes「D と E」のとおり):

| 項目 | 作り方 |
|---|---|
| D | B の fd を基準に乱数 10 文字で `mkdirat(0700)` (`EEXIST` は引き直し、16 回まで) → `O_RDONLY \| O_DIRECTORY \| O_NOFOLLOW \| O_CLOEXEC` で開く → `fstat` (実ディレクトリ・持ち主が実効 uid) → `fchmod(0711)` → `flock(LOCK_SH)` → 名前で `fstatat(AT_SYMLINK_NOFOLLOW)` して fd と `(st_dev, st_ino)` が同じか確かめる。違えば fd を閉じて作り直す。mode の付け方はハブの答え待ち (下の一覧の 6) |
| D を作る所 | bind の link-dir・link-file・thread-cwd・at と `ResolveForConnect` だけ。`base.mu` の下で 1 度だけ |
| resolve の E | 名前は `base.nextE` を 36 進にした物。D の fd を基準に `symlinkat`。`Cleanup` で `unlinkat` |
| 呼び出しごとの E | 名前は乱数 10 文字 (`EEXIST` は引き直し、16 回まで)。thread-cwd・at は D の中、既定の connect の link-file は B の直下。呼び出しの中で `unlinkat` |
| 指す先 | link-dir と thread-cwd・at はソケットのディレクトリの realpath。link-file は元のパス (相対パスなら cwd を前に付ける) |
| bind が失敗した時 | その呼び出しで作った E を消してからエラーを返す (link-file を実行時に見分けて次へ進む時も) |
| illumos / Solaris | `golang.org/x/sys/unix` に `Symlinkat` が無いので、B の実パスから `B/D/<名前>` を組んで `unix.Symlink` で作る (`symlinkat_none.go` を置き換える) |

綴り (SPEC-routes「綴りの形」のとおり。`link.go`):

| 綴り | 形 | 使う時 |
|---|---|---|
| procB | `/proc/<pid>/fd/<B の fd>/<D>/<E>[/<ファイル名>]` | Linux / Android で `/proc` を使え、`UsableCrossUID` でなく、sockaddr に入る |
| 実パス | `<B の実パス>/<D>/<E>[/<ファイル名>]` | sockaddr に入る (B がソケットのディレクトリの時は使わない) |

- `/proc` を使えるかは、`/proc/<pid>/fd/<B の fd>` を `stat` で引けることで確かめる (同じ物を指すことまで確かめるかはハブの答え待ち、下の一覧の 5)
- 既定の connect の link-file は実パスの `<B>/<E>` だけ

`Spelling` と診断の `Base` の値 (SPEC「綴りの性質 `Spelling`」、SPEC-routes「綴りの形」):

| 通った経路 | `Kind` | `Removable` | `Until` | `UsableCrossUID` | `UsableWithPrivateTmp` | `Base` |
|---|---|---|---|---|---|---|
| standard (絶対パス、abstract の名前) | `Original` | | | | | `""` |
| standard (相対パス) | `CwdRelative` | | | | | `""` |
| link-dir (procB) | `Linked` | true | `UntilProcess` | false | ハブの答え待ち (下の一覧の 7。推しは true) | 一時の置き場は `proc`、他は `sockdir` / `given` |
| link-dir (実パス) | `Linked` | true | `UntilCleanup` | `base.crossUID` | `!base.tmpPath` | `tmp` / `runtime` / `tmpdir` / `given` |
| link-file (実パス) | `Linked` | false | `UntilCleanup` | `base.crossUID` | `!base.tmpPath` | 同上 |
| thread-cwd・at | `Dangling` | | | | | `""` |

`Sweep` と `SweepBase` (SPEC「`sweep`」、SPEC-routes「D と E」):

- `Sweep` は `/tmp/sockat-<uid>`・`$XDG_RUNTIME_DIR/sockat`・`$TMPDIR/sockat-<uid>` のうち、あって B の確かめに通る物を対象にする。B を作らない。`SweepBase` は渡されたパスの B を対象にする (無ければ何もしない)
- B の直下のディレクトリを 1 つずつ `O_NOFOLLOW` で開き、持ち主が実効 uid の実ディレクトリなら `flock(LOCK_EX | LOCK_NB)` を試す。取れたら中の symlink を `unlinkat` し、D を `unlinkat(AT_REMOVEDIR)` で消す (空でなければ残す)。取れなければ触らない
- B の直下の symlink (既定の connect の E) には触らない

### OS ごとの経路の列

bind (`Listen`・`ListenEx`・`ListenUnixgram`・`ListenUnixgramEx`。SPEC「bind の順」):

| OS | 列 |
|---|---|
| Linux / Android | standard → link-dir (procB → 実パス) → thread-cwd |
| Apple の OS | standard → link-dir (実パス) → link-file → thread-cwd |
| FreeBSD | standard → link-dir (実パス) → at |
| NetBSD | standard → link-dir (実パス) → link-file |
| OpenBSD / illumos | standard → link-dir (実パス) |
| その他の Unix | standard → link-dir (実パス) → link-file (bind が失敗して元のパスに物が無ければ次へ) |

connect (`Dial`・`DialEx`・`DialUnixgram`・`DialUnixgramEx`。SPEC「connect の順」):

| OS | 列 |
|---|---|
| Linux / Android (`/proc` を使える) | standard → proc-direct → thread-cwd-direct → link-file |
| Linux / Android (`/proc` を使えない) | standard → relative → thread-cwd-direct → link-file |
| Apple の OS | standard → relative → widened (作らない。`skipped` に入れる) → thread-cwd-direct → link-file |
| FreeBSD | standard → at-direct → link-file |
| NetBSD / OpenBSD / illumos / その他の Unix | standard → relative → link-file |

- `ResolveForBind` は bind の列のうち link-dir と、macOS・NetBSD だけ link-file。`ResolveForConnect` は link-file (procB → 実パス) だけ
- その OS の列に無い経路を `skipped` に入れるかはハブの答え待ち (下の一覧の 4。推しは入れない。`/proc` を使えない Linux の connect は proc-direct を `skipped` に入れてから relative へ進む)
- `Options.Base` が相対パスか、最後がファイル名でない時は引数の誤り (ハブの答え待ち、下の一覧の 10)
- FreeBSD の connect の link-file は SPEC「未確定」。connect は最後の symlink を辿る (SPEC-routes「link-file」) ので作り、CI の FreeBSD の VM で確かめた結果をハブに知らせる
- thread-cwd・at の D は、`UsableCrossUID` で当たる B が無い時も普段の B (置き場 1〜4) に作る (ハブの答え待ち、下の一覧の 8)
- 手段は今の物を使う: thread-cwd は `inThreadCwd` (Linux は seccomp の filter が無い時だけ `unshare(CLONE_FS)` → `fchdir`、Apple は `__pthread_fchdir`)、at / at-direct は `atOp` (`bindat` / `connectat`)、thread-cwd-direct は `inThreadCwd` にソケットのディレクトリの fd とファイル名を渡す
- スレッドの cwd の goroutine は `UnlockOSThread` しない

### 試験の方針

- 経路は公開せず、試験は package の中から `config` を差し替えた `world` で経路を強制する。置き場 (`/tmp` の代わりの場所、`$XDG_RUNTIME_DIR`、`$TMPDIR`)、`/proc` の場所、スレッドの cwd を試すか、bind が symlink を辿るかを差し替える
- 公開 API の試験 (`package sockat_test`) は本物の `/tmp/sockat-<uid>` を使う。試験バイナリは `TestMain` の終わりに、自分が `defaultWorld` に作った D と E を消す (試験専用の口を `export_test.go` に置く)。置き場に残骸を溜めない
- cwd を変える試験と、生きているプロセスの D が要る試験 (sweep) は、試験バイナリを子プロセスで起こす
- 各試験の直前に「何を確かめ、なぜそうなるべきか」をコメントで書く

SPEC「実装が確かめる試験の観点」との対応:

| 観点 | 試験 | 走る所 |
|---|---|---|
| 短いパスの境界 | 標準に渡す長さちょうどは `standard`、1 バイト長いと経路。標準自身 (`net.ListenUnix`) で境界を確かめる | 全 OS |
| 綴りが当たる所 | link-dir・link-file・thread-cwd・at の `Addr()` の綴りを unlink / stat しても、cwd の同名ファイルと、fd の番号を使い回させた別のディレクトリの同名ファイルに当たらない | macOS、Linux (at は FreeBSD) |
| B の確認 | 途中が他人に書ける置き場・持ち主が違う B・symlink の B を使わず次へ進む (`sockat-<uid>.<乱数>` に落とす)。`Options.Base` は外れたら `ENOENT` / `ENOTDIR` / `EPERM` で、他の置き場に何も作らない | 全 OS (持ち主が違う物は root で走る Linux の docker) |
| 並行 | 多数の goroutine と複数の子プロセスが同時に長いパスの bind / connect をして、B が 1 つ・D がプロセスに 1 つで、全部通る | macOS、Linux |
| `sweep` | 子プロセスが生きている間はその D を消さず、終わった後は消す。D を作った直後に消された時は作り直す | macOS、Linux |
| `cleanup` | `Cleanup` の後に E が無く、2 回目は何もしない。D と B は残る | 全 OS |
| 既定の connect | link-file を強制した connect の後に B の直下が空で、D が作られていない。backlog が満杯でも待たずに返る | macOS、Linux |
| `remove` | ファイルが消え、listener は開いたまま。開いている間に置き換えた別のファイルは消さない。覚えられなかった時は listener を閉じてエラー | 全 OS |
| `ForBind` の `SocketFile()` | bind の前はエラー。bind の後の `Remove` は置き換えたファイルを消さない | 全 OS |
| thread-cwd・at | 強制して、プロセスの cwd も呼び出し元のスレッドの cwd も変わらず、呼び出しの後に E が無く、元のパスで送受信できる | macOS、Linux (unconfined)、FreeBSD |
| link-file の bind | 辿らない OS の振る舞いを `config` で作り、`skipped` に入って E が残らない。元のパスに物がある時は `EADDRINUSE` で次を試さない。実測した OS で辿るかの表が合っている | macOS (辿る)、Linux・FreeBSD・OpenBSD・illumos (辿らない)、NetBSD (辿る) |
| connect の経路 | proc-direct・relative・at-direct・thread-cwd-direct・link-file を 1 つずつ強制して届く。widened は `skipped` に入る | OS ごとの列 |
| 失敗をやり直さない | `ENOENT` / `EADDRINUSE` / `ECONNREFUSED` を返し、後の経路に何も作らない。link-dir・link-file の bind の失敗で E が残らない | 全 OS |
| relative と cwd | relative の途中で cwd が変わったら一般のエラー | 子プロセス、FreeBSD 以外 |
| macOS | bind は widened を使わない (253 バイトの connect が widened で通ることは、widened を作らないので確かめない) | macOS |
| ブロックしない connect | backlog が満杯で待たずに失敗する | macOS、Linux |
| 名前で終わらないパス、NUL | 何も作らずに `EINVAL`。NUL は短いパスでも。abstract の名前は標準に渡る | 全 OS (abstract は Linux) |
| カーネルが返すアドレス | 長いパスの listener・accept した接続・connect した接続の `Addr()`・`LocalAddr()`・`RemoteAddr()` が nil でなく `String()` で落ちない | 全 OS |
| 置き場の順と `Spelling` | 置き場を 1 つずつ使えなくして、B が次の置き場にでき、`Spelling` と `Base` が上の表の値になる。`UsableCrossUID` は満たす B が無ければ `Dangling` | macOS、Linux |

## ハブの答え (2026-11-21、統括から。3 言語共通として SPEC に入る)
