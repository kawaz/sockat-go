# v0.4.0 — ハブの DR-0017 (resolve と使い回す置き場) で作り直す

ハブの統括 (session 25352bb6) の依頼 (2026-11-21、ハブ main a91cf52b)。ハブの [DR-0017](https://github.com/kawaz/sockat/blob/main/docs/decisions/DR-0017-resolve-through-persistent-base.md) を、[SPEC](https://github.com/kawaz/sockat/blob/main/docs/SPEC-ja.md) (約束) と [SPEC-routes](https://github.com/kawaz/sockat/blob/main/docs/SPEC-routes-ja.md) (経路の作り方) どおりに実装する。適合試験の CLI はハブの docs/design/conformance.md の新しい入出力に合わせる。

## 依頼の要点

- resolve で、元のパスと同じ所を指し続ける短い綴りを作る (利用者ごとの B → プロセスごとの D (flock) → E の symlink。置き場は /tmp → $XDG_RUNTIME_DIR → $TMPDIR → ソケットのディレクトリ。綴りは procB → B の実パス)
- 既定の bind も綴りを残す。既定の connect は状態を残さない
- fork はしない (UseLastResort 等を消す)
- losses を綴りの性質 (Spelling) に、discard を remove にする
- 関数は SPEC の「関数」に合わせ、形は Go の慣習で決める (datagram の Listen / Dial 系、resolve の 2 つ、Sweep、Options の UsableCrossUID と Base)
- SEQPACKET と datagram の send_to は未決なので作らない
- widened を作れない扱いは今のまま (外すかは Go 側で判断してハブに知らせる)
- 互換は気にしない (利用者は kawaz のプロダクトだけ)。古い API・経路・文書は残さず消す

## 決まり

- SPEC と食い違う所・SPEC で決まらない所は、直し方を決める前にハブの統括に知らせる (推測で埋めない)
- 版は v0.4.0 の見込み。publish は全言語が揃ってハブの適合試験が通り、kawaz の OK が出てから。それまで push も bump もしない (手元の commit で進める)
- ハブの `just conformance` (手元と `--on linux`) で 3 言語の差を見る
- 進み具合と詰まった所を節目でハブの統括に send する

## ハブで追加中の細部 (決まり次第知らせが来る)

- 診断の base に Options.base の時の値 (given の予定)
- link-dir / link-file で bind して失敗した時は E を消してからエラー
